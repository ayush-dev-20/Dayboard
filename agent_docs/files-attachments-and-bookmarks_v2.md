# Feature: Files, attachments and bookmarks

**Phase:** V2 (feature 09)
**Status:** In progress. Everything works on the server-backed app against the `memory` driver. `pnpm storage:smoke` passed against the real B2 bucket on 2026-10-09 (region `eu-central-003`, path style off, download header overrides honoured); the app itself has not been exercised against B2 in a browser, and nothing works offline (features 03 to 05 were skipped on purpose).
**Date:** 2026-10-08

## What was built

- **Attachments** on notes, tasks and projects: an **Attachments** section (hairline list, "Attach files" button, drop zone) with progress, Cancel, Retry, per-row validation messages ("Too large: max 10 MB", "This file type isn't supported."), Download and Delete ("File removed."). Files go **straight from the browser to storage** (an XHR PUT to a presigned URL, so there is real progress); the server only issues an *intent* (checks owner, type, size, allowance, rate) and *finalizes* (checks size and the first bytes, then marks the file ready). Downloads go through `/api/files/{id}`, which checks the session and redirects to a 60-second signed URL.
- **Blocks in the editor** (`image`, `file`, `bookmark`, top-level atoms; notes and task descriptions): `/image`, `/file`, `/bookmark`, paste of a picture, drop of files. An image block has an editable caption, a viewer (Esc closes), and shows progress, "Couldn't upload. Retry" or "File removed" instead of ever showing a broken picture. A lone web address pasted on an empty line stays a link and offers **Keep as link / Link with page title / Bookmark card** (Enter on the default keeps the link and carries on). A bookmark stores a snapshot of the preview in the document; its menu has Refresh, Convert to link, Remove; a page that can't be read is a plain link with "Couldn't load a preview."
- **Link previews** are fetched **by the server** (`/api/link-preview`) through an SSRF-guarded fetch (private, loopback, link-local, metadata, mapped and odd-encoded addresses refused; the connection is pinned to the checked address; every redirect re-checked; 5 s, 512 KB, 3 redirects; failures reveal only `BLOCKED` or `FAILED`). Cached per person (7 days, failures 1 hour).
- **Resizable pictures:** in an editable note or task, a picture has a thin handle on its left and right edge (`image-resize.tsx`, maths in `src/lib/editor/image-size.ts`). Drag either one: the picture is centred, keeps its proportions, follows the pointer (so the width changes by twice the distance), never goes below 64 px wide or 64 px tall (a wide picture's minimum width is raised to keep it 64 px tall) and never above its column; one save per drag (one undo), Esc cancels. The right handle is a keyboard slider (arrows 16 px, Shift 64 px, Home minimum, End column); double-click either handle returns to the picture's own size. Stored as `width` in whole pixels on the `image` node (64 to 4000, otherwise dropped); no value means the picture's own size, at most the column.
- **Allowance:** 500 MB per person (`STORAGE_QUOTA_MB`) and a global cap (`STORAGE_TOTAL_LIMIT_MB`, default 9000, `STORAGE_FULL` is checked first). Settings → Account → Storage shows the person's usage. Deleting a file removes its stored object **and its row in the same request** (`deleteAttachment`), so space is freed at once; the object is deleted **by version id** (see the B2 note below), so nothing is left hidden in the bucket.
- **Gallery cover:** a note whose text holds a picture block shows the first one as the card's cover.
- **Provider decision** is ADR 0010 (Backblaze B2 through the S3 API; R2 is the planned fallback). The provider is hidden behind `StorageService`; `s3` (production), `memory` (tests, forced when `E2E=true`) and `disk` (local dev) adapters. With no `STORAGE_DRIVER` the feature is **hidden**, not broken (no section, no slash items, routes answer NOT_FOUND).

## Why

Notes and tasks need files, and the app runs on Vercel + Neon where a function can't hold files or carry big bodies. Private storage + direct upload + short-lived signed URLs keeps bytes off the server, and the S3 contract keeps the provider replaceable. A block holds an attachment **id**, never an address, so a pasted or edited document can't point at a file the person doesn't own; every route re-checks ownership.

## What was deferred

- **Offline uploads and "Not available offline"** (§6, §9; E2E case 4 and the offline half of case 6): need features 03 to 05 (Dexie, the sync engine). The upload manager is a plain store with `startUpload/retryUpload/cancelUpload`, so a queue can sit behind it later.
- **Background jobs (feature 08 does not exist):** `cleanupPending` (unfinished uploads after 24 h), `purgeExpired` (rows still `DELETED`/`REJECTED` because storage refused, and files whose owner is gone for good) and `pruneLinkPreviews` are plain functions in `src/db/mutations/`. `cleanupPending` and `purgeExpired` run for the signed-in person when they start an upload intent, and `purgeExpired` also after a `GET /api/files` list (via `after()`). **Correction (2026-10-09): the first build never called `purgeExpired` at all and kept deleted files for 30 days, which is why deleted files stayed in Backblaze.** Register all three as job handlers when feature 08 lands; then the opportunistic calls can go. Until then, files of a note deleted for good are only removed when that person next uploads or opens a note with a file list.
- **Real B2:** the bucket exists and CORS is applied (done by the owner with `b2 bucket update --cors-rules`; the S3 operation names are `s3_put`, `s3_get`, `s3_head`). Still to confirm by hand: the lifecycle rule "keep only the last version" (a console-made bucket has none, so deleted files keep counting), the $0 caps, the one-bucket key, and the `STORAGE_*` values and production origin on Vercel. The smoke test passed on 2026-10-09; re-run it after any change of key, bucket, SDK version or CORS rule.
- **Copy out of the app:** a picture or file block copies as nothing into other apps (it holds only an id); a bookmark copies as a link; inside Dayboard the internal flavour keeps the blocks (the spec's "image data when the browser allows it" is not built).
- Not built: image resizing or thumbnails (out of scope), width control for pictures (the `width` attribute is stored and honoured but nothing in the UI sets it), a project page's "Attachments" empty state is the same plain text as notes.
- Not checked: Safari, Firefox, a real phone, Docker. No design file exists for these screens; built from `DESIGN.md`.

## Hand-off notes

- **The S3 client must be built with `requestChecksumCalculation` and `responseChecksumValidation` = `"WHEN_REQUIRED"`** (SDK 3.729+ adds a CRC32 header B2 rejects, on presigned PUTs too). A unit test asserts both; the SDK is pinned to one exact version. The presigned PUT **signs `content-type`**, so the browser must send the returned `headers` unchanged. Never call bucket-level APIs (`HeadBucket`, `ListBuckets`): a bucket-restricted key is refused.
- **Keys never contain the file name:** `u/{userId}/{yyyy}/{mm}/{attachmentId}/{128-bit hex}`. The name lives only in the row (`original_name`, sanitized) and in the download header. (The owner kind and id were briefly added to the path and taken out again at the owner's request; the owner is only in the database row.)
- **Deleting on B2 is by version.** A plain `DeleteObject` on a versioned B2 bucket only hides the file (the data stays and counts against the 10 GB, and a console-made bucket has no lifecycle rule). `s3.ts` `delete` therefore does a `HeadObject` to read the `VersionId` and deletes that version; it falls back to a plain delete if no id comes back, and treats a missing object as deleted. `pnpm storage:smoke` step 8 proves it against the real bucket (a head of the deleted version must be not found; passed 2026-10-09). The lifecycle rule "keep only the last version" stays recommended as a safety net.
- **Image block internals:** `imageStopEvent` in `file-nodes.tsx` replaces Tiptap's default `stopEvent` for the image view, so pointer events on a resize handle never reach ProseMirror (otherwise the draggable block would start a native drag) while the caption box and buttons still work. The frame is `w-fit mx-auto max-w-full` and the caption box is `w-0 min-w-full` so its built-in width never widens the frame.
- **Not found is the answer for everything not yours.** Another person's file, a missing file, a file whose owner is in Trash, a deleted file: all `NOT_FOUND`. A client-suggested attachment id is used only if free, in any state, for anyone, so an id collision never reveals whether someone else has it. Files are hidden while their owner is in Trash by a join at read time (no write hooks); permanent delete of the owner lets the purge remove the file.
- **Download redirect `Cache-Control: private, max-age=45`**, not the spec's 300: the signed URL lives 60 s, so a longer cache would serve a dead address. Recorded in ADR 0010.
- **Quota counts `READY` + `PENDING`.** A global advisory lock serializes intents (so two people can't both slip under the global cap); the rate limit (30 intents a minute) is counted from rows, not memory, so it works across serverless instances.
- **Size and type are enforced at finalize** (a presigned PUT can't limit size): the object's real size and the first 4 KB are checked, and a mismatch is `REJECTED` and the object deleted. SVG, HTML and scripts are never accepted.
- **Editor tests in jsdom** mock `@/actions/notes`, `@/components/files/upload-manager` and `@/components/files/api` (see `tests/unit/files-clipboard.test.ts`); jsdom has no layout, so stub `document.elementFromPoint` for drops.
- **Paste order:** `onPaste` in `src/lib/editor/clipboard/index.ts` runs the paste rules **before** the "files only" early return, so the `image-files` rule (priority 50) can claim a screenshot paste. It claims only when the clipboard has an image file **and no text**.
- **Dev database:** run `pnpm db:migrate` (migration 0009) before opening the app. **`.env.local` currently points `DATABASE_URL` at the Neon production database**: `pnpm db:migrate` from the repo applies to *that*. On Vercel/Neon migrations are manual; 0008 and 0009 both need applying there before this feature ships. Never run it without the owner's go-ahead.
- To try it locally without a bucket: `STORAGE_DRIVER=disk` (files in `.storage-dev`, git-ignored). Real B2 setup, CORS and caps are in the feature doc §3.2 to §3.5.

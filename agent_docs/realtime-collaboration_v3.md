# Feature: Real-time collaboration on notes

**Phase:** V3 (feature 05)
**Status:** Done for slices A, B and C of the spec, with the gaps below. It only runs where the collaboration service runs; the current Vercel + Neon deployment cannot run it, so there shared notes keep using ordinary saves.
**Date:** 2026-11-16

## What was built

- **ADR 0019** (`docs/decisions/0019-realtime-collaboration-yjs-hocuspocus.md`): Yjs with the Tiptap collaboration extensions; Hocuspocus as a separate process from the same image; seeding on the server; projection back into `notes`; fallback; one instance.
- **The service** (`src/collab/service.ts`, entry `src/collab/server.ts`, bundled by `scripts/build-collab.mjs` to `dist/collab.mjs`; `pnpm collab` builds and runs it; a `collab` service in `docker-compose.yml`'s full profile; the Dockerfile copies `collab.mjs`). One document per note, named by the note id. `onAuthenticate` verifies the app's 60-second token and then **asks the database** (`resolveAccess`), sets read-only connections, and enforces 20 connections per note and per person. Every minute it re-checks every open connection (drops those that lost access, downgrades to read-only). `POST /internal/recheck` (header `x-collab-secret`) does the same at once; the app calls it after remove, role change, stop sharing and leave (`recheckCollabAccess`, a no-op without the service). `GET /health`. Limits: 1 MB per update and 50 messages a second (the connection is closed), documents over 2 MB turn read-only.
- **Persistence** (`src/collab/docs.ts`, tables `note_collab_docs` and `note_snapshots`, migration `0026`): `loadLiveDoc` seeds once under a per-note advisory lock, and seeds again when the note was changed some other way (`base_version` and `projected_version` both differ from `notes.version`). `storeLiveDoc` projects after 2 s quiet, at most every 10 s, through `projectNoteFromLive` (`db/mutations/notes.ts`), which reuses what an ordinary save uses (text, titles of linked notes, `note_links`) with no version check, and sets `updated_by_user_id`. The body goes through `sanitizeDoc`; a body that cannot be cleaned keeps the last good projection. When the last connection closes and nobody else can edit, `retireIfNoEditors` projects a last time, takes a `LAST_DISCONNECT` snapshot and deletes the live row. Snapshots every 10 minutes while editing; the newest 30 per note are kept (`maintenance.prune_note_snapshots`, daily 03:30 UTC, migration `0027`).
- **Conversion** (`src/lib/collab/convert.ts`): the body is the Y.XmlFragment `default` and the title and emoji are the Y.Map `meta`. The ProseMirror schema is built with `getSchema(createExtensions(...))` without node views, so the service uses the editor's own nodes; a test round trips every node type (paragraph, headings, marks, lists, tasks, code, quote, divider, callout, toggle, table of contents, table, note link, sub-note).
- **App side:** `POST /api/collab/token` (access to read, and at least one other person who may edit, else `NOT_FOUND`; role edit or read from `resolveAccess`), `noteEditorIds` (`src/modules/permissions/editors.ts`: grantees with EDITOR on the note, a note above it or its project; none for journal entries or Trash), `SHARING_ENABLED` plus `COLLAB_URL` and both secrets give `env.collabEnabled`. While a `note_collab_docs` row exists **and someone can edit and the service is configured**, ordinary content, title and emoji saves are refused with `CONFLICT` ("being edited together", `assertNotLive`); otherwise the stale row is deleted by the next ordinary save.
- **Editor:** `useLiveNote` (`components/notes/use-live-note.ts`) fetches the token, loads Yjs, the provider and the extensions only then (ordinary notes load none of it), reconnects with a fresh token each time, and reports phase, role, peers and a polite announcement. `RichTextEditor` takes `collab: { extensions }` (history off through `createExtensions({ collab })`, text from the document). `NoteEditor` swaps `sync` for a live one: title and emoji go to the `meta` map, remote renames arrive by observing it, the "More actions" and ordinary save status are replaced by `LivePresence` (avatars with initials, "Reconnecting… your changes are kept", polite "X joined" and "X left" at most every 5 s). Cursors and name tags come from the Collaboration Caret extension, styled in `globals.css` (the tag fades after 3 s; none for reduced motion). A `beforeunload` warning shows while disconnected. If the service does not sync within 8 seconds on first load, the note falls back to ordinary saves.
- **Tests:** unit (`collab-token`, `collab-convert`: 23), integration against the real service in-process with real WebSocket clients (`collab-service`: 13, `collab-token`: 3), and `e2e/collab.spec.ts` (three browsers: both write, names and avatars, a viewer cannot type, a rename crosses, the note's columns follow). Playwright now starts the service on port 1235 as a second web server.

## Why

Two people editing one note is the point of sharing it. Yjs merges concurrent edits without conflicts and Hocuspocus is the standard server for it. `notes` stays the truth for search, lists, backlinks and AI, kept current by projection, so nothing else had to change.

## What was deferred

- **Hosting.** Vercel and Neon cannot hold a WebSocket. Until a host that runs Node continuously is chosen (the owner's call), `COLLAB_URL` stays unset in production and shared notes use the ordinary save-and-conflict flow. The `Dockerfile` and Compose service exist but were not run (Docker is not installed on the owner's machine); `pnpm collab` was.
- **Not built:** the in-memory update buffer limit of 100 KB while offline (a note offline stays editable in memory), "Recover unsent changes" from a device draft after closing a tab (only the `beforeunload` warning), "Last edited by <name>" under the title, metrics (connection counts), Caddy `/collab` (there is no Caddyfile in the repo), the `BEFORE_ROLLBACK` snapshot (nothing rolls back yet), a state over 2 MB telling the person why (the note turns read-only; no message in the editor), the second E2E cases (kill and restart the service, `COLLAB_URL` unset fallback, Axe on the presence row).
- **Offline note editing** (V2 features 04 and 05 for notes) does not exist, so there is nothing to reconcile.
- A commenter on a live note connects read-only like a viewer (comments are feature 06).

## Hand-off notes

- **The service bundle must not use the `react-server` condition** (the worker does): the editor's node views need the real `react`. `build-collab.mjs` stubs `server-only` and replaces `@/actions/*` with throwing functions, because the node definitions import the browser's action stubs.
- **A new editor node must round trip through Yjs.** Add a sample to `tests/unit/collab-convert.test.ts`. Attributes must be JSON.
- **Anything that writes `notes.content_json` outside the editor** while a note is live would be overwritten at the next projection. Ordinary saves are refused; keep that guard (`assertNotLive`) on any new writer.
- **Access changes should call `recheckCollabAccess()`** (the sharing service does); the 60-second re-check is only the backstop.
- Env: `COLLAB_URL` (ws or wss), `COLLAB_TOKEN_SECRET`, `COLLAB_INTERNAL_SECRET` (32+ characters each, the same on the app and the service), `COLLAB_PORT` (1234), `COLLAB_INTERNAL_URL`. **Migrations `0026` and `0027` are applied to the test database only.**
- Related: `permissions-and-sharing_v3.md` (who may edit, `resolveAccess`), `notes-projects-tags_v1.md` (`useNoteSync`, the ordinary path), `nested-notes-links-sidebar-tree_v2.md` (`note_links`), `editor-blocks-and-lists_v2.md`, `background-worker-and-jobs_v2.md`, ADR 0019.
